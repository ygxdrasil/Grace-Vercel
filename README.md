# Grace

A personal assistant with a voice, a memory, and a firm sense of what she may not
do without asking.

Grace is built for one person. She listens for her name, answers out loud, and
remembers what she learns about you between sessions. She is deliberately not a
coding agent and not a general chatbot — she is meant to help run a life.

**Status: Phase 1.** Voice conversation and memory work. Calendar, email, smart
home, and web research are not connected yet; Grace will say so rather than
pretend otherwise.

## Running her

**Prerequisites:** Node.js 20+ and a Gemini API key
([free from AI Studio](https://aistudio.google.com/apikey)).

```bash
npm install
cp .env.example .env.local     # then put your key in it
npm run dev                    # http://localhost:3000
```

For a production run, `npm run build && npm start` serves the built app and the
API together on one port.

Use Chrome or Edge. The wake word relies on the Web Speech API, which Firefox and
Safari don't implement fully. Typing to her works in any browser.

### Talking to her

Turn on the microphone with the button at the bottom left — the browser asks for
permission once. After that she waits quietly for her name.

- **"Grace, what did we talk about yesterday?"** — one breath, one request.
- **"Grace."** … then wait for the orb to brighten, and speak.

She goes deaf while thinking and speaking, so she never answers her own voice.
The orb shows which state she is in: slow breathing while waiting, bright and
rippling while listening, a turning arc while thinking.

### Checking she works

```bash
npm run selftest
```

Runs a real conversation through the whole pipeline with the model stubbed out —
SSE streaming, memory persistence, context assembly, profile extraction,
compaction, and the guardrails — and asserts on each. Thirteen checks, no API
key needed, a few seconds.

What it deliberately does not cover is the Gemini call itself. That one needs a
live key, and the first thing to try once you have one is simply saying hello.

## Putting her online

She runs two ways from the same code. On your own machine she keeps her memory
in a file. Deployed, she keeps it in Redis — because serverless has no permanent
disk, and a file there would vanish between messages.

To deploy on Vercel:

1. Get this source into a GitHub repository (the files themselves, not a
   `.bundle` — that's an archive git has to unpack, and uploading it just stores
   the box rather than the code).
2. In Vercel, **Add New → Project**, and import that repository.
3. Under **Storage**, add a Redis store and connect it to the project. That
   injects `KV_REST_API_URL` and `KV_REST_API_TOKEN` on its own.
4. Under **Settings → Environment Variables**, add:
   - `GEMINI_API_KEY` — your key
   - `GRACE_PASSWORD` — what you'll type to get in
   - `GRACE_SECRET` — a long random string, encrypts her memory
5. Redeploy.

**She refuses to run deployed without `GRACE_PASSWORD`.** Not a warning — she
returns an error to every request instead of sitting open at a public address
where anyone who finds it could read what she knows about you.

Visit `/api/health` on the deployed URL to confirm the wiring: it reports
whether the key is present, which storage she found, and whether memory is
encrypted. `"storage":"Redis"` means the database is connected;
`"storage":"local disk"` means it isn't, and she'll forget everything.

## What she remembers

Everything you say is kept. Alongside the transcript she builds a profile —
facts, preferences, routines, and goals — and folds older conversations into a
running summary so context survives past the model's window.

All of it lives in `.grace/` on your own disk. Nothing goes to a hosted database,
and `.grace/` is gitignored. Open the panel (top right) to read everything she
has learned, delete any single item, or clear the transcript.

Set `GRACE_SECRET` in `.env.local` to encrypt it at rest with AES-256-GCM. Keep
that value safe — memory written under one secret cannot be read back without it.

Her replies are generated by the Gemini API, so the conversation itself is sent
to Google. Worth knowing before discussing anything you would not want leaving
the machine.

## What she will not do

Two limits are enforced in code, not merely requested in the prompt:

- She never sends a message or email without your approval of that exact message.
- She never spends money without your approval.

Both are locked in the panel, and the API refuses to relax them. Everything else
— calendar, smart home, locks, research — has a confirmation setting you can
change as those connections come online.

## How it fits together

```
shared/types.ts     contracts shared by both sides
server/
  api.ts            HTTP surface; chat streams over SSE
  persona.ts        who Grace is, and her hard limits
  memory.ts         transcript, profile, rolling summary
  learn.ts          pulls durable facts out of each exchange
  actions.ts        confirmation policy, structurally enforced
  store.ts          encrypted JSON on local disk
  llm/              provider seam — Gemini today, swappable
src/
  hooks/useGrace.ts the state machine tying it together
  voice/            wake word, transcription, speech
  components/       orb, transcript, composer, memory panel
```

The API key stays server-side; the browser never sees it. In development the same
Express app is mounted straight into the Vite dev server, so `npm run dev` is one
process and there is exactly one API in both environments.

Grace runs on Gemini Flash because it has the most workable free tier. The
`LlmProvider` interface exists so that stays a reversible decision.
